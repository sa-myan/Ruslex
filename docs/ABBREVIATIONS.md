# Abbreviations as a first-class Ruslex entry category

Ruslex has **three entry types**: `word`, `expression`, and
`abbreviation`. A category is **not** a part of speech. Thus:

- `МГУ`: abbreviation, NOUN, a letter-name initialism; no inferred ordinary
  dictionary stress or conjugation/declension paradigm.
- `вуз`: abbreviation, NOUN, a lexicalized acronym that declines
  (`вуза`, `вузу`, ...). Its forms may be generated by pymorphy3.
- `т. д.` and `т. е.`: written abbreviations, normally no independent
  ordinary word stress; the OCR scanner treats each as **one** token rather
  than the useless letters `т` and `д`.

The stable database lemma remains lowercased, as in the legacy dictionary.
The public interface renders conventional undotted initialisms in uppercase,
while lexicalized words such as `вуз` and dotted abbreviations remain in
their normal written form. Original OCR casing remains in context evidence.

## How existing abbreviations are found

The read-only `abbreviations plan` scans active entries and reports:

1. **Known lexical abbreviations** (explicit high-precision list): can be
   automatically reclassified after a backup, keeping all senses, examples,
   relationships and textbook occurrences.
2. **Meaning evidence** such as 'abbreviation', 'acronym' or 'stands for':
   review-only suggestions, not forced changes.
3. **Uppercase occurrences** are *not* used to reclassify existing
   dictionary entries: historical textbook headings produce convincing
   but entirely false positives such as `УРОК`, `ПАРК` and `ВСЕГДА`.
   For **new OCR material**, unfamiliar uppercase sequences in running prose
   can be offered as review-only abbreviation hypotheses. The model must
   confirm the lexical meaning before admitting such an entry.

Hidden entries are logically absent and never reclassified. New OCR processing
offers both word and abbreviation interpretations for unfamiliar uppercase
tokens; the model must select a validated option or abstain. A real acronym
outside the known list can be categorized through the regular entry editor.
Low-confidence OCR fragments stay in the existing review queue.

## Safe release sequence

First run `sh scripts/verify_book_pipeline.sh` in the isolated development
worktree. It exercises the migration on a **disposable** dictionary copy,
alongside form generation and the Django API smoke tests. Production is not
modified.

After PR acceptance, with the repository updated and the production image
still stopped/undeployed for the new feature:

~~~sh
./process.sh abbreviations plan
./process.sh abbreviations rehearse
./manage.sh backup
./process.sh abbreviations init --confirm
./process.sh abbreviations categorize --confirm
./process.sh abbreviations plan
~~~

`init` is a one-time SQLite CHECK-constraint extension. SQLite cannot modify
the constraint in-place; this rebuilds **only** the lexemes table inside a
transaction, preserving the same primary keys and columns, preserving
user-defined indexes and triggers, checking all foreign keys, and taking a
verified backup first. `categorize` is a separate, idempotent confirmed step
with its own backup. The website and Django admin DB do not perform this
migration.

Do not start a new book import until this schema step has been completed:
otherwise older SQLite rejects `entry_type='abbreviation'`.

## Everywhere else

- Search and entry-type filters include abbreviations. Senses, notes, links,
  tags and occurrences work as with words.
- An abbreviation can be an expression constituent. It is not automatically
  turned into a multiword expression.
- Pronunciation audit/backfill and AI stress-exception reviews operate on
  ordinary **word** headwords; abbreviations do not get spurious guessed stress.
  Lexicalized abbreviations can still receive manually verified pronunciation.
- Morphological paradigms skip ordinary initialisms, while a small known set
  of inflecting acronyms may receive their real forms. Attested textbook
  surface forms remain separate from generated inflections.
- AI enrichment may add known expansions and meanings, but cannot invent
  an expansion from arbitrary capital letters.
- Review, book-status and audit reports retain the distinct category.

If the current 43-case stress AI run includes `мгу`, it will become stale
after reclassification. This is intentional: do not reuse a run containing
different live evidence; start a new run for the remaining ordinary words.
